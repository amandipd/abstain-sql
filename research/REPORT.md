## Flags — things that change the plan

1. **Qwen3.5-2B is not a plain text model.** `Qwen/Qwen3.5-2B` is a *multimodal* model (image/video input) with a hybrid architecture alternating Gated DeltaNet and attention layers. It is the riskiest of the three candidate models for tooling: it required vLLM nightly at release, and its card warns the 2B size is "more prone to thinking loops" ([model card](https://huggingface.co/Qwen/Qwen3.5-2B)). Upstream vLLM (a fast batched text-generation engine) supports it in-tree by v0.19.0 ([release notes](https://github.com/vllm-project/vllm/releases/tag/v0.19.0)). Keep SmolLM3-3B ready as a drop-in fallback.
2. **Unsloth's embedded vLLM cannot serve Qwen3.5.** Unsloth's own RL guide says to set `fast_inference=False` for Qwen3.5 — i.e., no fast vLLM generation inside Unsloth — which removes Unsloth's main speed advantage for the primary model ([Unsloth RL guide](https://unsloth.ai/docs/basics/reinforcement-learning-rl-guide)). This settles the stack choice in TRL's favor (question 3).
3. **"Gemma 4 E2B" is really 5.1B total parameters in memory.** The control model `google/gemma-4-E2B-it` has 2.3B *effective* (active per token) but 5.1B total parameters including embeddings, so its training memory footprint is that of a 5B model ([model card](https://huggingface.co/google/gemma-4-E2B-it)). Budget VRAM accordingly, or use SmolLM3-3B as the control.
4. **Novelty is narrowed, not killed, by three near-misses.** BAR-SQL (RL + abstention credit, 1.7B, text-to-SQL, Jan 2026), Reinforced Hesitation (the exact +1/0/−λ reward, 1.7B, logic puzzles, Nov 2025), and RLSR (RL optimizing the risk–coverage trade-off directly, 7–8B, QA/math, Jul 2026) each hold two of the three ingredients. No paper holds all three. Any write-up must cite and differentiate all three in its opening (details in [related_work.md](related_work.md)).
5. **Plain conformal risk control does not bound the promised guarantee.** Conformal risk control (CRC — a statistical recipe that picks a confidence cutoff on held-out data so an error target provably holds on average) bounds the *unconditional* rate of "answered AND wrong." The brief's promise — "error ≤ α on the queries it answers" — is *selective risk*, a conditional ratio, which CRC does not bound. **Learn-then-Test (LTT)** — which treats each candidate cutoff as a hypothesis test and gives a guarantee holding with high probability — is the correct tool ([CRC paper](https://arxiv.org/abs/2208.02814); [LTT paper](https://arxiv.org/abs/2110.01052)). See question 5.
6. **Empty-result reward hacking interacts badly with an abstain reward of 0.** Many Spider/BIRD gold queries return empty results; a junk query that also returns nothing scores "correct" (+1) while honest abstention earns 0, so the RL optimizer would learn to emit junk SQL instead of abstaining on hard questions. Arctic-Text2SQL-R1 filtered ~1,400 BIRD and ~1,700 Spider examples for exactly this ([arXiv:2505.20315](https://arxiv.org/html/2505.20315v2)). Filter gold-empty examples and use multi-instance execution checks *before* any reward tuning.
7. **No license blocker.** Spider 1.0 and BIRD are CC BY-SA 4.0 (use freely with attribution; redistributed modified data keeps the same license); TrustSQL and EHRSQL are CC BY 4.0 (attribution only); Spider 2.0's repo shows MIT ([sources in Q2](#2-data)). Nothing prohibits training.
8. **The only unmeasured cost input is end-to-end training throughput.** No published benchmark exists for GRPO steps/hour on a ~2B model with LoRA + vLLM on one GPU. The 20-step smoke test (≤ $0.60, estimate) must run before any full run commits budget ([compute_estimate.md](compute_estimate.md)).

## 1. Novelty check

**Verdict: the exact combination — RL training + explicit abstention reward + risk–coverage evaluation, on a ≤4B model, in text-to-SQL — appears unpublished as of 2026-11-04.** Every pairwise combination exists. (Risk–coverage curve = a plot of the error rate among answered questions against the fraction of questions answered; the standard way to evaluate a model that may decline.)

What exists, by cell:

- **RL for text-to-SQL, no abstention:** Arctic-Text2SQL-R1 (7B/14B/32B, GRPO, reward 1/0.1/0 on execution match; BIRD dev 68.9–70.5) ([arXiv:2505.20315](https://arxiv.org/abs/2505.20315)); SQL-R1 (3B/7B/14B, composite reward; 3B gets 54.6 BIRD dev) ([arXiv:2504.08600](https://arxiv.org/abs/2504.08600)); Reasoning-SQL (14B, partial rewards incl. LLM judge) ([arXiv:2503.23157](https://arxiv.org/abs/2503.23157)); plus a dozen newer systems (CSC-SQL, SLM-SQL at 0.5–1.5B, Think2SQL, MTIR-SQL-4B, SkyRL-SQL, Graph-Reward-SQL, ReViSQL-BIRD, Progress-SQL, SQL-Trail, EXPO-SQL, …). None has an abstain action or selective-prediction metrics. Small-model anchor: well-trained ≤4B RL models reach roughly **54–67% execution accuracy on BIRD dev** (execution accuracy = the generated SQL counts as right only if running it returns the same result as the reference query), with ~67% needing 64-sample voting (SLM-SQL 1.5B) ([arXiv:2507.22478](https://arxiv.org/pdf/2507.22478)).
- **Abstention in text-to-SQL, no RL:** TrustSQL (benchmark + penalty score RS(c)) ([arXiv:2403.15879](https://arxiv.org/abs/2403.15879)); EHRSQL-2024 shared task (ranking metric RS(10); none of the 8 teams used RL; no team achieved positive RS(N)) ([arXiv:2405.06673](https://arxiv.org/html/2405.06673v2)); post-hoc confidence/selective-prediction studies (Somov & Tutubalina AAAI 2025; Richardson 2026; adaptive-abstention conformal pipeline) — all inference-time add-ons.
- **RL-trained abstention outside SQL:** Reinforced Hesitation (+1/0/−λ, Dr.GRPO, Qwen3-1.7B, logic puzzles; reports Pareto frontiers over λ, not standard risk–coverage) ([arXiv:2511.11500](https://arxiv.org/html/2511.11500v2)); Rewarding Intellectual Humility (ternary reward sweep, Granite-3.3-2B and Qwen-3-4B, multiple-choice QA, no risk–coverage per abstract) ([arXiv:2601.20126](https://arxiv.org/abs/2601.20126)); TruthRL, RLKF, KARL, Knowing-When-to-Quit (sizes/metrics partly UNVERIFIED from abstracts); and RLSR, which reports full risk–coverage curves and AURC but trains no abstain action and uses 7B/8B models ([arXiv:2607.03528](https://arxiv.org/html/2607.03528v1)).
- **The single RL + abstention text-to-SQL paper: BAR-SQL** (Qwen3-1.7B + GRPO; refusals scored by text similarity to a gold refusal; no penalty parameter c, no abstain token, **no risk–coverage, no RS(c), no Spider/BIRD results**; private enterprise benchmark only) ([arXiv:2601.10318](https://arxiv.org/html/2601.10318)).

**Smallest differentiating angle** (if a reviewer treats the near-misses as prior art): train the ternary penalty-swept reward with an *explicit structured abstain action* in text-to-SQL with execution-grounded rewards, evaluate with risk–coverage curves *and* TrustSQL's RS(c) on public benchmarks, and add the conformal/LTT guarantee layer plus the schema-shift stress test — none of BAR-SQL, Reinforced Hesitation, or RLSR has any of those last three elements. Two caveats the notes flag: 2026 preprint volume is high and OpenReview was not crawled, so an under-review collision is possible; and Reinforced Hesitation's λ-sweep is functionally close to a risk–coverage analysis, so cite it explicitly.

## 2. Data

**Licenses (verified 2026-11-04):** BIRD — CC BY-SA 4.0 ([bird-bench.github.io](https://bird-bench.github.io/); its *earlier* license is UNVERIFIED). Spider 1.0 — CC BY-SA 4.0 ([yale-lily.github.io/spider](https://yale-lily.github.io/spider)). Spider 2.0 — repo shows MIT; whether the dataset files carry a separate license is UNVERIFIED ([github.com/xlang-ai/Spider2](https://github.com/xlang-ai/Spider2)). TrustSQL — CC BY 4.0 ([repo](https://github.com/glee4810/TrustSQL)). EHRSQL — CC BY 4.0, but the underlying MIMIC/eICU patient databases sit behind PhysioNet data-use agreements ([repo](https://github.com/glee4810/EHRSQL)).

**Unanswerable/ambiguous coverage:** TrustSQL: ~2,468 of 21,356 questions unanswerable (~11.6%), **test-only**, five labeled types (column-surface, column-related, column-unrelated, non-sql, out-of-domain) ([arXiv:2403.15879](https://arxiv.org/html/2403.15879v2)). EHRSQL: unanswerables are 33% of validation/test, **none in training** ([ar5iv 2301.07695](https://ar5iv.labs.arxiv.org/html/2301.07695)). BIRD, Spider 1.0, Spider 2.0: no labeled unanswerables; both BIRD and Spider 2.0 have publicly acknowledged ambiguity problems, and a VLDB audit reports pervasive gold-label errors in BIRD Mini-Dev and Spider 2.0-Snow ([VLDB p931](https://www.vldb.org/pvldb/vol19/p931-jin.pdf)).

**Contamination (benchmark leakage into pretraining):** no direct measurement exists for Spider or BIRD in Qwen or Gemma — UNVERIFIED in both directions. Circumstantial evidence: a GPT-3.5 study found a significant drop on the unfamiliar Termite set vs. Spider ([arXiv:2402.08100](https://arxiv.org/abs/2402.08100)); Qwen2.5-Coder's decontamination list names only code/math benchmarks ([arXiv:2409.12186](https://arxiv.org/pdf/2409.12186)); Gemma 3's report describes generic eval-set removal with no benchmark list ([arXiv:2503.19786](https://arxiv.org/abs/2503.19786)). Also relevant: RL gains measured on contaminated benchmarks can be illusory ([arXiv:2507.10532](https://arxiv.org/html/2507.10532v1)). Qwen3.5-2B is newer than every contamination study found.

**Decision: hybrid, defaulting to synthetic.** Synthetic training data (fresh schemas → no contamination, free injection of unanswerables, full control of gold-empty results) with **BIRD dev as the external, untouched evaluation set**, plus TrustSQL/EHRSQL as external reliability benchmarks for RS(c) comparison. Existing datasets alone fail because neither provides unanswerable *training* examples (see above).

**Synthetic generator design** (blueprint = SynSQL-2.5M's pipeline, Apache-2.0, generated entirely with open models: web tables → LLM designs a multi-table business schema → complexity-controlled SQL generation → SQL-to-question back-translation → execution-based majority-vote filtering; 96% of its databases judged realistic) ([arXiv:2503.02240](https://arxiv.org/html/2503.02240v2)):
- Schema generation with realistic names: follow SynSQL's scenario-inference step; Gretel's 100-domain list is a second source of domain variety ([HF dataset](https://huggingface.co/datasets/gretelai/synthetic_text_to_sql)).
- Table filling: populate 3–5 *different* data instances per schema (this doubles as the test-suite checker, below), with value distributions that make empty results rare and detectable.
- Question templates: SQL-first, back-translated to natural language, SynSQL-style.
- Injected categories with known labels: **unanswerable** (ask about a column deliberately removed — TrustSQL's column-surface/related/unrelated types), **ambiguous** (undefined metric — BAR-SQL's "metric rejection" mutation is prior art for the mutation style), **out-of-scope** (non-SQL asks, TrustSQL's non-sql/out-of-domain types). The notes found **no prior art synthesizing unanswerable text-to-SQL at scale** — a secondary contribution.
- Caveat: SynSQL was largely generated *by* Qwen2.5 models, so reusing it (rather than the pipeline) is self-distillation-adjacent for a Qwen student.

**Test-suite accuracy (Zhong et al. 2020):** verified real and fit for purpose. `test-suite-sql-eval` (Apache-2.0, SQLite) executes predicted and gold SQL against *multiple* distilled database instances per schema so a wrong query can't match by coincidence; it is Spider's official metric ([github.com/taoyds/test-suite-sql-eval](https://github.com/taoyds/test-suite-sql-eval); [arXiv:2010.02840](https://arxiv.org/abs/2010.02840)). BIRD's harness executes on a single database only ([github.com/bird-bench/mini_dev](https://github.com/bird-bench/mini_dev)). Gap: no maintained package *generates* test suites for new synthetic databases (Zhong's generation repo exists; current state unchecked) — for synthetic data, generate the 3–5 instances at schema-creation time instead.

## 3. Training stack

**Recommendation: TRL GRPOTrainer (v1.17.x) with vLLM colocate on a single GPU.** (GRPO = Group Relative Policy Optimization, an RL algorithm that scores a group of sampled answers against each other instead of training a separate value network; colocate = vLLM shares the training GPU, the TRL default.) Scorecard against the brief's four requirements, from the notes' comparison:

- **Qwen3.5 support:** TRL via current transformers + vLLM ≥0.17 (LoRA fix in 0.19) — yes. `verifiers`: UNVERIFIED for the hybrid architecture. Unsloth: embedded vLLM unsupported → `fast_inference=False` (flag 2).
- **LoRA (low-rank adapters — training a small add-on instead of all weights):** TRL `peft_config` — yes. `verifiers` RLTrainer "supports LoRA" (mirror-sourced, UNVERIFIED). Unsloth — yes, best VRAM story.
- **Custom SQL-executing reward:** all three accept arbitrary Python; TRL additionally supports **async** reward functions (`asyncio.gather`), which matters when one slow query would otherwise stall a whole generation group ([TRL GRPOTrainer docs](https://huggingface.co/docs/trl/main/en/grpo_trainer)).
- **Single GPU:** TRL colocate is default-documented with memory knobs (`vllm_gpu_memory_utilization`, sleep mode, `beta=0.0` skips the reference model). `verifiers` is churn-heavy (GRPOTrainer → RLTrainer → Taskset model in one year) and oriented to Prime Intellect's stack. Unsloth is the VRAM leader — keep as fallback for the control model or if a 24GB GPU becomes the cost-saving path.

**Abstain mechanism: structured output, not a special token.** Emit `{"sql": ..., "abstain": bool, "reason": ...}` (or a reserved tag) and parse it in the reward. Reasons: every RLVR abstention paper found uses emitted text; a new vocab token forces training of the embedding/output layers (`modules_to_save`) — a large VRAM hit at 150K–262K-token vocabularies — and **TRL's fused LM-head scoring raises an error when a PEFT adapter touches `lm_head`** ([TRL releases](https://github.com/huggingface/trl/releases)); vLLM's Qwen3.5 LoRA path needed an upstream fix as late as v0.19.0. The [IDK]-token line (NeurIPS 2024) used full continued pretraining, not RL ([arXiv:2412.06676](https://arxiv.org/abs/2412.06676)). No head-to-head token-vs-text study under GRPO exists — open question, not worth this project's budget.

**Loss settings** (consensus of Dr. GRPO paper, TRL docs, Arctic/SQL-R1 settings):
- `loss_type="dr_grpo"` + `scale_rewards=False` — Dr. GRPO removes the per-response length division and the reward standard-deviation division, two normalizations shown to bias response length ([arXiv:2503.20783](https://arxiv.org/html/2503.20783v2)). TRL's default `"dapo"` addresses length bias differently; "dr_grpo vs dapo" is a cheap ablation.
- KL coefficient β = 0 (Dr. GRPO's setting; TRL default; skips the reference model and saves memory). Add β ≈ 1e-3 (Arctic's value) only if degeneration appears.
- Group size 8 (SQL-R1's and TRL's default; Arctic found no gain beyond 16 rollouts). Learning rate ~1e-6, clip 0.2 (optional upper 0.28).
- Generation cap 1024–2048 tokens with `mask_truncated_completions=True` — TRL's 512 default is too small for think-then-SQL; SQL-R1 used 2048; Qwen3.5-2B's thinking-loop proneness argues for a hard cap.

**Reward-hacking design points:**
- *Abstain-on-everything at high c:* a documented failure mode ("abstention trap", KARL; a fixed abstention reward "can lead a model to refuse nearly everything", AWA-RL) ([arXiv:2604.22779](https://arxiv.org/abs/2604.22779); [alphaXiv 2607.10738](https://www.alphaxiv.org/abs/2607.10738)). Mitigations: sweep c across runs (the run matrix does this), log abstention rate per training step with an alarm threshold, and keep answerable questions ≥ ~70% of the training mix (the Hallucination Tax paper restored refusal with just 10% unanswerable data) ([arXiv:2505.13988](https://arxiv.org/abs/2505.13988)).
- *Empty-result matching:* flag 6. Filter gold-empty training examples (Arctic's fix) and/or require non-empty agreement across instances.
- *Degenerate SQL matching on small tables:* use the multi-instance test-suite check as the reward's correctness oracle, not single-DB execution; add a per-query timeout (2–5 s) in the reward sandbox (SQL-R1 limits execution time; timeouts also keep one slow query from stalling a GRPO group).
- *General shaping:* keep the reward minimal (+1 / 0 / −c, plus at most a small format gate); Arctic argues complex shaped rewards invite "superficial reward hacking", and SQL-R1 saw hacking when execution/result terms were underweighted ([arXiv:2505.20315](https://arxiv.org/html/2505.20315v2); [arXiv:2504.08600](https://arxiv.org/html/2504.08600v5)). No length bonus.

## 5. Calibration and guarantee

**Comparison (weakest to strongest guarantee):**
1. *Simple threshold selection* — pick the cutoff where error on a calibration split equals α. No finite-sample guarantee; test error lands above α roughly half the time when the estimate sits at the boundary. This is what the closest text-to-SQL study did (frontier reporting, no certificate) ([arXiv:2607.06799](https://arxiv.org/abs/2607.06799)).
2. *Conformal risk control (CRC)* — guarantees the **expected** loss ≤ α for a monotone, bounded loss, exactly up to O(1/n), assuming exchangeability (calibration and test points statistically interchangeable). Fits the loss "answered AND wrong" (an unconditional rate). **It does not bound selective risk** — the error rate *among answered queries* — because that is a ratio of expectations, and CRC also cannot handle non-monotone risks (its own Proposition 1) ([arXiv:2208.02814](https://arxiv.org/abs/2208.02814)).
3. *Learn-then-Test (LTT)* — reframes cutoff selection as multiple hypothesis testing: for each candidate cutoff, test "true error > α" with a concentration bound (e.g., an exact binomial test — treating each answered calibration item's right/wrong as a coin flip and asking how unlikely the observed error count would be), keep only cutoffs where the hypothesis is rejected. Gives "selective risk ≤ α with probability ≥ 1−δ over the calibration draw" — the statement readers will assume from the brief's wording. Use fixed-sequence testing (walk cutoffs from conservative to permissive, stop at first failure) to avoid the full multiple-testing penalty ([arXiv:2110.01052](https://arxiv.org/abs/2110.01052); recipe corroborated in [arXiv:2609.01375](https://arxiv.org/pdf/2609.01375), snippet-level). Geifman & El-Yaniv's SGR is the 2017 special case of the same idea ([arXiv:1705.08500](https://arxiv.org/abs/1705.08500)).

**Pick: LTT for the headline guarantee** (selective risk ≤ α with confidence 1−δ), optionally reporting the simpler CRC bound on "answered AND wrong" alongside. Cost of rigor: LTT is more conservative at the same calibration size; with α = δ = 0.05 expect to need several hundred *answered* calibration points (sizing intuition, not a cited result).

**Confidence signal:** the RL abstain decision is a binary action — it cannot be thresholded, so it supplies base selectivity, not a dial. Calibrate on top of it: primary = **sequence log-probability** (the model's own probability of the emitted query — cheap, white-box, and published evidence says it beats self-checking and verbalized confidence for SQL) ([arXiv:2411.16742](https://arxiv.org/abs/2411.16742)); alternative = **k-sample execution agreement** (sample k queries, compare execution results — stronger ranking signal, k× the cost, used by the strongest conformal-abstention paper) ([arXiv:2405.01563](https://arxiv.org/abs/2405.01563)). No paper evaluates calibrating an RL-trained abstain policy's own signal for SQL — an open slot this project fills.

**Assumptions, stated plainly:** the guarantee requires new queries to be exchangeable with the calibration data — same kinds of schemas, questions, and difficulty. It is *marginal*: it holds on average over re-draws of the calibration set, and any single calibration set can land above α. The certificate is relative to the correctness oracle: if "correct" means execution-match on one database instance, a lenient instance inflates certified reliability ([arXiv:2609.25938](https://arxiv.org/pdf/2609.25938), snippet-level) — state the oracle (multi-instance test suites) explicitly.

**Shift experiment design:** (1) partition by schema family so calibration and test never share a schema (synthetic families, or TrustSQL's four source datasets); (2) calibrate at α ∈ {0.05, 0.1, 0.2} on family A; (3) report realized selective risk, coverage, and the overshoot (realized − α) on family B with bootstrap intervals; (4) include an i.i.d. control (disjoint halves of the same family) to separate finite-sample noise from shift; (5) all ordered A→B pairs → an overshoot matrix. Expected outcome: visible breakage — the best proxy is fine-tuned verifiers dropping ~0.78 → ~0.66 AUROC on unseen schemas ([arXiv:2607.06799](https://arxiv.org/abs/2607.06799)). No published calibration-transfer study for text-to-SQL exists — this experiment is novel per the notes' search.

## 6. Evaluation protocol

**Metrics** (all execution-based or statistical; no LLM judge anywhere):
- Execution accuracy via **multi-instance test suites** (the reward's own oracle, held fixed for eval).
- Coverage (fraction answered) and selective risk (error rate among answered).
- **AURC** (area under the risk–coverage curve — one number for the whole trade-off; lower is better) and E-AURC (AURC minus a perfect-ranking baseline). Definitional fine print lives in the full texts of [arXiv:1805.08206](https://arxiv.org/abs/1805.08206) (fetch before quoting).
- **RS(c)** at c ∈ {0, 10, N} — TrustSQL's penalty score: +1 correct, 0 abstain-on-answerable, −c wrong or answering an unanswerable, +1 abstain-on-unanswerable; at c=N one confidently wrong answer wipes out a perfect score on everything else ([arXiv:2403.15879](https://arxiv.org/html/2403.15879v6)). Beating the abstain-everything floor (RS = 50 on TrustSQL's 50/50 test mix) is the minimum bar.
- Tokens per query; GGUF latency on the local laptop via llama.cpp's Vulkan backend (GGUF = a quantized model file format for local inference).
- Report realized risk and coverage at each certified threshold, showing whether the guarantee held.

**Baselines:** (a) base model prompted to abstain when unsure — published anchor: frontier models prompted this way abstain <1% of the time with error rates >10% ([arXiv:2511.11500](https://arxiv.org/html/2511.11500v2)); (b) base model with self-consistency thresholding (abstain unless k samples agree — TrustSQL found 5-sample unanimous voting "notably strong"); (c) accuracy-only GRPO (the same training minus the abstain action — isolates what the abstention reward buys); (d) 1–2 frontier models through an API, prompted to abstain. Published full-coverage reference points for ≤4B RL models: ~54–67% BIRD dev EX (see Q1).

**Statistics:** ≥2 seeds; bootstrap confidence intervals (re-sampling results many times to measure how much each number wobbles) over *both* test items and seeds; interquartile mean over seeds per the rliable playbook ([arXiv:2108.13264](https://arxiv.org/abs/2108.13264)); and — because conformal guarantees are averages over calibration draws — re-draw the calibration/test split many times and report the distribution of realized risk around α (the CRC paper's own protocol: 1000 splits). Note: a canonical citation for paired item-level bootstrap in NLP still needs fetching (notes gap).

## 7. Positioning

All four BI copilots surveyed (Snowflake Cortex Analyst, Databricks Genie, ThoughtSpot Spotter, Hex) manage wrong answers with the same stack: a human-curated semantic layer, a library of human-verified queries, and show-the-SQL-so-humans-check — curation before the question, inspection after the answer. Abstention is a shallow UX fallback (Genie asks clarifying questions or says it "can't answer"; Cortex Analyst returns suggested alternative questions for ambiguous asks), and **no vendor publishes an abstention rate, refusal threshold, or calibrated confidence** — Snowflake's `confidence` API field only reports whether a pre-verified query was reused ([Cortex Analyst REST API](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-analyst/rest-api); [Talk to Genie](https://docs.databricks.com/aws/genie/talk-to-genie)). Academic abstention benchmarks (TrustSQL, PRACTIQ, Ambrosia+) exist but use bare academic schemas with no semantic layer. An open abstention benchmark plus a small reference model with measured risk–coverage operating points and a stated guarantee fills the unoccupied middle — calibrated behavior at answer time — and gives customers the comparison ("how often does it answer wrongly vs. decline") that no product enables today.

## Recommendations

1. **Go.** Model: Qwen3.5-2B primary with SmolLM3-3B as tooling fallback and control (prefer it over Gemma 4 E2B given the 5.1B memory footprint). Stack: TRL GRPOTrainer + vLLM colocate, LoRA, async SQL-executing reward, `dr_grpo` loss, β=0, group 8, cap 1024–2048.
2. **Reward:** +1 test-suite-verified correct / 0 structured abstain / −c wrong; sweep c across runs (e.g. c ∈ {0.5, 1, 4}, anchored on Reinforced Hesitation's λ range and TrustSQL's c=10 being brutal); strict format gate; per-query timeout; gold-empty examples filtered.
3. **Data:** synthetic generator (SynSQL-style pipeline + TrustSQL-taxonomy injections, ~30% unanswerable/ambiguous), 3–5 data instances per schema; BIRD dev untouched as external eval; TrustSQL/EHRSQL for RS(c) comparison.
4. **Guarantee:** Learn-then-Test on sequence log-probability over the trained policy; report CRC's joint-rate bound as secondary; run the schema-shift overshoot matrix.
5. **Sequence:** smoke test before any full run; frontier-API baselines capped at a few dollars; write-up leads with the novelty triangulation against BAR-SQL / Reinforced Hesitation / RLSR.

## Go/no-go verdict

**GO.** The kill condition in the brief (someone already published RL + abstention reward + risk–coverage at ≤4B) was checked first and is not met. Novelty is real but narrow — it rests on the triple combination, the SQL domain with execution-grounded rewards, public-benchmark RS(c)/risk–coverage reporting, and the guarantee layer — so the near-misses must be cited prominently. Budget fits with ~2× headroom at central estimates. The two biggest execution risks are tooling friction from Qwen3.5-2B's hybrid multimodal architecture (mitigated by the SmolLM3-3B fallback and the smoke test) and abstention collapse at high c (mitigated by the c-sweep, the training-mix ratio, and per-step abstention-rate logging).
