# Prior Work: Abstention/Reliability in Text-to-SQL and RL-Trained Selective Prediction

Research date: 2026-11-04. All claims below were verified by fetching the cited page on this date unless marked UNVERIFIED. "Risk-coverage curve" = a plot of error rate (risk) against the fraction of questions the model chooses to answer (coverage). "Abstention" = the model declining to answer. "RL" = reinforcement learning. "GRPO" = Group Relative Policy Optimization, a popular RL algorithm for LLMs. "RLVR" = RL with verifiable rewards (reward computed by checking the answer, not by a learned judge).

## Key Question 1: What exactly are TrustSQL, the EHRSQL 2024 shared task, AmbiQT, and AMBROSIA?

### Takeaway
TrustSQL and EHRSQL 2024 define the penalty-based Reliability Score RS(c) that is the standard abstention metric in text-to-SQL; neither uses RL nor reports risk-coverage curves. AmbiQT and AMBROSIA are ambiguity benchmarks (two-or-more-valid-SQL settings), not abstention benchmarks — neither has a penalty/abstention metric.

### Cited Findings

**TrustSQL (arXiv 2403.15879; Lee, Chay, Cho, Choi; KAIST; v1 Mar 2024, v6 Jul 2024; listed as "under review", no venue stated on arXiv)**
- Task: given a question, output SQL for feasible questions and abstain on infeasible ones (schema-incompatible, beyond-SQL, needs-external-knowledge) — [arXiv abs](https://arxiv.org/abs/2403.15879)
- Exact per-sample score phi_c(x), five cases (Q = feasible set, Q^c = infeasible set, g(x)=1 means the model answers, g(x)=0 means it abstains, Acc(x) = execution accuracy): 1 if feasible+answered+correct; 0 if feasible+abstained; **−c** if feasible+answered+wrong; **−c** if infeasible+answered (any SQL); 1 if infeasible+abstained. Overall score = mean of phi_c over all N samples. c is "the ratio of the negative impact to the positive impact" — [arXiv HTML v6](https://arxiv.org/html/2403.15879v6)
- Penalty values used: c = 0 (reduces to accuracy), c = 10, and c = N (N = number of evaluated samples; one wrong answer wipes out everything) — [arXiv HTML v6](https://arxiv.org/html/2403.15879v6)
- Data: ATIS, Advising, EHRSQL, Spider; totals 2,555 / 2,769 / 7,473 / 8,561 questions; ~2.5K infeasible questions (476/533/934/527), test-set only; five infeasible types (column-surface, column-related, column-unrelated, non-sql, ext-know) — [arXiv HTML v6](https://arxiv.org/html/2403.15879v6)
- Models: T5-3B (SQL generation), SQLCoder-7b-2 fine-tuned as infeasible-question classifier and SQL-error detector; GPT-3.5-turbo-0125 generation with GPT-4o classifiers; prompting methods SQLPrompt, DIN-SQL, MAC-SQL — [arXiv HTML v6](https://arxiv.org/html/2403.15879v6)
- Abstention mechanisms tested: pipeline (separate pre-generation classifier + post-generation error detector); unified with uncertainty thresholds — MaxEnt and MaxProb (output-probability thresholds) and FeatMD/FeatRMD (Mahalanobis feature-distance thresholds); API variants: few-shot "not_answerable" label and 5-sample unanimous-agreement voting — [arXiv HTML v6](https://arxiv.org/html/2403.15879v6)
- No RL anywhere; no risk-coverage curves (selective generation is only cited as related work) — [arXiv HTML v6](https://arxiv.org/html/2403.15879v6)
- Code/data: [github.com/glee4810/TrustSQL](https://github.com/glee4810/TrustSQL) — [arXiv abs](https://arxiv.org/abs/2403.15879)

**EHRSQL 2024 shared task (arXiv 2405.06673; Lee, Kweon, Bae, Choi; ClinicalNLP workshop @ NAACL 2024)**
- Task: reliable text-to-SQL on the MIMIC-IV Demo EHR database; answer answerable clinical questions, abstain on unanswerable ones (adopts TrustSQL's reliability definition; adds adversarial unanswerable questions and unseen templates) — [ACL Anthology](https://aclanthology.org/2024.clinicalnlp-1.62), [arXiv HTML v2](https://arxiv.org/html/2405.06673v2)
- Identical RS(c) cases as TrustSQL: 1 (answerable, correct SQL), 0 (answerable, abstained), −c (answerable, wrong SQL), −c (unanswerable, any SQL), 1 (unanswerable, abstained); averaged and reported as a percentage. **Main ranking metric: RS(10)**; also reports RS(0) and RS(N). Minimum scores: 0% at c=0, −1000% at c=10, −100·N% at c=N — [arXiv HTML v2](https://arxiv.org/html/2405.06673v2)
- Data: train 4,674 answerable + 450 unanswerable (5,124); valid 931 + 232 (1,163); test 934 + 233 (1,167); 100 templates in train, 134 in valid/test (34 unseen) — [arXiv HTML v2](https://arxiv.org/html/2405.06673v2)
- 8 teams (from 100+ applicants). Winner LG AI Research & KAIST: self-training with pseudo-labeled unanswerable questions, fine-tuned ChatGPT; RS(0) 88.17, RS(10) 81.32, RS(N) −711.83. **No team achieved positive RS(N)**; the trivial abstain-all baseline scores 20.0 on all penalties — [arXiv HTML v2](https://arxiv.org/html/2405.06673v2)
- Team abstention mechanisms (none used RL): unanimous 3-model ensemble agreement (PromptMind); log-probability thresholding with threshold set from the validation unanswerable ratio (ProbGate); self-consistency across samples (KU-DMIS); null output via in-context learning on SQLCoder-7b-2 (Project PRIMUS); logistic-regression unanswerability detector + T5-3B + executability check (AIRI NLP); SQLCoder-7b-2 detector+generator with log-probs + executability (LTRC-IIITH); NB/SGD/CatBoost/CodeLlama-7b ensemble detectors (Saama) — [arXiv HTML v2](https://arxiv.org/html/2405.06673v2)
- Links: dataset [github.com/glee4810/ehrsql-2024](https://github.com/glee4810/ehrsql-2024); leaderboard [Codabench competition 1889](https://www.codabench.org/competitions/1889/); ProbGate code [github.com/venzino-han/probgate_ehrsql](https://github.com/venzino-han/probgate_ehrsql) — [arXiv HTML v2](https://arxiv.org/html/2405.06673v2)

**AmbiQT (arXiv 2310.13659; Bhaskar, Tomar, Sathe, Sarawagi; EMNLP 2023 main, pp. 7053-7074)**
- Benchmark of 3,000+ examples where one question maps to **two** plausible SQL queries; four ambiguity types: column synonyms, table synonyms, join ambiguity, precomputed aggregates — [ACL Anthology](https://aclanthology.org/2023.emnlp-main.436), [GitHub](https://github.com/testzer0/AmbiQT)
- Evaluation is top-k coverage (do both valid SQLs appear in the top-k outputs?), not abstention; no penalty metric. Proposes LogicalBeam (plan-based template generation + constrained infilling), up to 2.5x better at surfacing all candidate SQLs in top-k — [arXiv](https://arxiv.org/abs/2310.13659v1)
- Code: [github.com/testzer0/AmbiQT](https://github.com/testzer0/AmbiQT)

**AMBROSIA (arXiv 2406.19073; Saparina & Lapata; NeurIPS 2024 Datasets & Benchmarks, Spotlight)**
- Questions with three ambiguity types — scope ambiguity, attachment ambiguity, vagueness — each with all interpretations and their SQL; databases generated from scratch so the ambiguity survives database context; finds even the most advanced LLMs struggle to identify and interpret ambiguity — [arXiv abs](https://arxiv.org/abs/2406.19073), [NeurIPS proceedings](https://proceedings.neurips.cc/paper_files/paper/2024/hash/a4c942a8405cc910f0a833d28d2573cc-Abstract.html)
- No abstention/penalty scoring mentioned on the abstract page; in the original paper the all-interpretations-found metric is very low (a later paper reports Llama3-70B achieved only 1.9% AllFound) — [AmbiSQL HTML citing it](https://arxiv.org/html/2508.15276v1); size/metric details beyond this: UNVERIFIED (not on the pages fetched)

### Inferences
- The TrustSQL/EHRSQL RS(c) family is the de-facto penalty metric for text-to-SQL abstention; it is a pointwise penalty score, not a risk-coverage curve — no sweep over abstention thresholds is reported in either paper, so risk-coverage evaluation in this exact setting appears to be open.
- All abstention mechanisms in both benchmarks are inference-time add-ons (classifiers, thresholds, voting) or supervised fine-tuning; none train the generator itself to abstain via a reward.

### Gaps
- TrustSQL's arXiv page lists no venue ("under review"); whether it was later published at a venue was not determined.
- AMBROSIA's exact dataset size and official code link were not on the fetched pages (the full PDF would have them).

## Key Question 2: Newer 2025-2026 work on abstention / trust / unanswerable questions in text-to-SQL

### Takeaway
2025-26 text-to-SQL abstention work splits into (a) detection-style approaches (probes, prompting) with no RL, and (b) one RL paper — BAR-SQL (Jan 2026, Li Auto) — which trains Qwen3-1.7B with GRPO and a hybrid reward that credits natural-language refusals on unanswerable questions, but reports no risk-coverage curves and no RS(c).

### Cited Findings
- **BAR-SQL / "Boundary-Aware NL2SQL: Integrating Reliability through Hybrid Reward and Data Synthesis" (arXiv 2601.10318; Tian, Zhuo, Zhang, Shen, Wu — Li Auto Inc. + BUPT; submitted 15 Jan 2026).** Closest text-to-SQL prior to RL-trained abstention. Pipeline: Seed-Mutation data synthesis (1,575 templates, 30 business dimensions, 832 entities; mutations include ambiguity and "knowledge rejection" cases) → full-parameter SFT (~20K instances) → GRPO (G=16, clip 0.2, KL beta 0.01, lr 1e-6). Reward = weighted sum of accuracy (1.0 for execution-matched SQL; 0.5·AST-F1 + 0.5·dense result score fallback for wrong SQL; for natural-language answers, embedding cosine similarity to the gold response with cutoffs at 0.96/0.90), format, grammar (1 if both prediction and gold are natural language), and length terms (weights 1.5/1.0/0.9/0.8). Abstention/refusal is plain natural-language text in the `<answer>` block (e.g. a clarification request) — **no abstain token, no explicit negative penalty for wrong SQL, no penalty parameter c**. Base model **Qwen3-1.7B** (≤4B). Releases Ent-SQL-Bench (1,262 held-out instances, ~50% unanswerable/interactive). Results: BAR-SQL 91.48% average vs Claude-4.5-Sonnet 48.02%, GPT-5 46.01%, base Qwen3-1.7B 8.47%, SFT-only 67.55% (per-category accuracy judged partly by GPT-4o). **No risk-coverage curves, no RS(c), no coverage metrics.** Code: [github.com/TianSongS/BAR-SQL](https://github.com/TianSongS/BAR-SQL) — [arXiv HTML](https://arxiv.org/html/2601.10318)
- **LatentRefusal (arXiv 2601.10398; Fudan University; Jan 2026; Findings of ACL 2026).** Treats refusal as answerability gating: a lightweight probe on the LLM's hidden activations predicts answerability; avg F1 ~88.5% on Llama-3.1-8B and ~88.8% on Qwen-3-8B across four benchmarks, ~2 ms overhead. Probe/classifier approach, no RL — [arXiv HTML](https://arxiv.org/html/2601.10398v1) (details from abstract/search snippets; full metric list UNVERIFIED)
- **"Query Carefully: Detecting the Unanswerables in Text-to-SQL Tasks" (arXiv 2512.21345; Zurich University of Applied Sciences; Dec 2025).** Prompting-based unanswerable detection for biomedical SQL; releases OncoMX-NAQ (80 no-answer questions, 8 categories); best prompting ~0.8 detection accuracy; weakest on missing-value queries. No RL — [arXiv](https://arxiv.org/abs/2512.21345?context=cs) (details from search snippets; UNVERIFIED beyond abstract level)
- **Ambrosia+ / Shakespeare-SQL ("To RAG or Not to RAG... Under Ambiguity", IEEE).** Extends AMBROSIA with 2,535 unanswerable questions (6,777 total, 16 domains); "disambiguate first, parse later" pipeline reaches 73.0% full coverage vs DFPL's 30.5% with 89% fewer SQL queries — [IEEE listing via Georgia Tech](https://scp.cc.gatech.edu/external-news/ieee-xplore-rag-or-not-rag-question-effective-text-sql-generation-under-ambiguity); figures from abstract only, UNVERIFIED
- **PRACTIQ (arXiv 2410.11076).** Conversational text-to-SQL dataset with four categories of ambiguous and four categories of unanswerable queries — [arXiv HTML](https://arxiv.org/html/2410.11076v1) (noted from search results; details UNVERIFIED)
- **AmbiSQL (arXiv 2508.15276).** Interactive ambiguity detection and resolution for text-to-SQL (asks the user rather than abstaining) — [arXiv HTML](https://arxiv.org/html/2508.15276v1)
- **RL-for-text-to-SQL without abstention (context):** SQL-R1 (arXiv 2504.08600, NeurIPS 2025; 3B/7B checkpoints on HuggingFace; execution-reward RL; 88.6% Spider / ~67% BIRD; [code](https://github.com/IDEA-FinAI/SQL-R1)) — [NeurIPS page](https://nips.cc/virtual/2025/poster/116624); Reasoning-SQL (arXiv 2503.23157; GRPO with partial rewards: LLM-judge, syntax, schema-linking, n-gram) — [arXiv](https://www.arxiv.org/pdf/2503.23157v2); Arctic-Text2SQL-R1 (arXiv 2505.20315, GRPO, execution-only reward) — [arXiv HTML](https://arxiv.org/html/2505.20315v1). None of these include an abstention action or reward per the fetched summaries.
- **ReToolSQL (arXiv 2608.27796).** Tool-augmented text-to-SQL trained with GRPO/DAPO-style dynamic sampling; whether it rewards abstention is UNVERIFIED (snippet did not show it) — [arXiv PDF](https://arxiv.org/pdf/2608.27796)

### Inferences
- BAR-SQL is the single published case of "RL + some abstention credit" in text-to-SQL found in this search, and it does not do penalty-calibrated abstention (no c), does not use an abstain token, and does not evaluate selective-prediction trade-offs (no risk-coverage, no RS(c)). Its evaluation is on a proprietary-style enterprise benchmark, not Spider/BIRD/EHRSQL.
- The mainstream RL text-to-SQL line (SQL-R1, Reasoning-SQL, Arctic) optimizes execution accuracy only; abstention is absent from their reward designs.

### Gaps
- Could not verify BAR-SQL's appendix (training algorithm details) — page truncated at 100K characters.
- No search found any paper evaluating RL-trained text-to-SQL models on TrustSQL or EHRSQL-2024 RS(c) metrics; absence of evidence here, but the space of 2026 preprints is large.

## Key Question 3: Who has trained abstention with RL in the general LLM literature (plus classic selective prediction)?

### Takeaway
A dense 2024-2026 line now trains abstention with RL: RLKF (2024, RLHF-style), TruthRL and Reinforced Hesitation (ternary rewards in GRPO/Dr.GRPO), Rewarding Intellectual Humility (RLVR with swept abstention reward on 2B/4B models), KARL (adaptive knowledge-boundary reward), Knowing-When-to-Quit (abstention as an RL action, theory), and RLSR (reward that directly targets the area under the risk-coverage curve). Classic selective prediction (SelectiveNet, Deep Gamblers) supplies the risk-coverage framing but predates LLMs/RL.

### Cited Findings

**RL-trained abstention (chronological)**
- **RLKF — "Rejection Improves Reliability: Training LLMs to Refuse Unknown Questions Using RL from Knowledge Feedback" (arXiv 2403.18349; Xu et al.; 2024).** RLHF-style: automatically generates preference pairs from knowledge feedback (no human labels), trains a reward model, then RL-fine-tunes the policy; starts from Llama-2 Chat; evaluated on math questions; key framing: answer as much as possible while explicitly refusing unknown questions — [arXiv](https://arxiv.org/abs/2403.18349v2). Risk-coverage reporting: not mentioned in fetched material (UNVERIFIED either way).
- **"The Hallucination Tax of Reinforcement Finetuning" (arXiv 2505.13988; Song, Shi, Zhao; USC; Findings of EMNLP 2025).** Shows standard RFT (reinforcement fine-tuning) collapses refusal (can cut refusal rates by >80%; e.g. Qwen2.5-7B-Instruct refusal on UMWP 0.30 → 0.08); fix is data-side, not reward-side: mixing 10% SUM (Synthetic Unanswerable Math) into RFT restores refusal (Qwen2.5-7B on SUM test 0.01 → 0.73; generalizes to SelfAware) with small accuracy cost — [arXiv](https://arxiv.org/abs/2505.13988v1), [ACL Anthology](https://preview.aclanthology.org/lei-li-partial-disambiguation/2025.findings-emnlp.112). Some figures via secondary summaries — treat exact numbers as UNVERIFIED pending the paper's tables.
- **TruthRL (arXiv 2509.25760; Wei et al.; Meta + UVA/UW; v1 Sep 2025; ICML 2026).** GRPO with a ternary reward distinguishing correct answers / hallucinations / abstentions; "various backbone models" (sizes not stated on the abstract page — UNVERIFIED); four knowledge-intensive benchmarks; hallucination rate 43.5% → 19.4%, truthfulness 5.3% → 37.2%; online GRPO beats DPO and iterative DPO. No risk-coverage mention on the abstract page. Code: [github.com/facebookresearch/TruthRL](https://github.com/facebookresearch/TruthRL) — [arXiv abs](https://arxiv.org/abs/2509.25760). Secondary sources state reward values +1/0/−1 — UNVERIFIED against the paper itself — [Moonlight review](https://www.themoonlight.io/review/truthrl-incentivizing-truthful-llms-via-reinforcement-learning).
- **Reinforced Hesitation — "Honesty over Accuracy" (arXiv 2511.11500; Mohamadi (TTIC/UCSD), Wang, Li; Nov 2025).** Ternary RLVR reward: **+1 correct, 0 abstain, −λ wrong** (λ ∈ {0,1,2,5,10,20}; format violations −0.5λ); abstention is the literal phrase "I don't know" inside `<answer>` tags; algorithm Dr.GRPO; model **Qwen3-1.7B** (≤4B); trained on Knights & Knaves logic puzzles (80k train); also evaluates 11 frontier models zero-shot on GSM8K/MedQA/GPQA (they abstain <1% of the time with error rates >10%). Reports **Pareto frontiers of error vs abstention across λ, coverage-safety tradeoffs, and conditional accuracy** (84% at λ=0 → >99% at λ=10; λ=1 cuts errors from ~15% to <2%) — but **no standard risk-coverage curve or named selective-risk/AURC metric**. Proposes cascades using abstention as a routing signal (five-tier cascade: 88.1% accuracy at 2.2 avg queries; self-cascade 77.5% → 92.5%). No code link found in fetched content — [arXiv HTML v2](https://arxiv.org/html/2511.11500v2)
- **"Rewarding Intellectual Humility: Learning When Not To Answer" (arXiv 2601.20126; Jha et al.; 27 Jan 2026).** RLVR with ternary reward **(−1 incorrect, r_abs abstain, +1 correct)** and a sweep over r_abs; models **Granite-3.3-2B-Instruct and Qwen-3-4B-Instruct (both ≤4B)**; domains MedMCQA and Hendrycks Math (multiple choice); findings: moderate r_abs (~−0.25 to 0.3) cuts incorrect responses without severe accuracy loss; larger models more robust to abstention incentives; open-ended QA fails without SFT abstention warmup. Metrics: incorrect-rate and accuracy; **no risk-coverage metrics mentioned in the abstract** (full paper UNVERIFIED). Code: [github.com/Mystic-Slice/rl-abstention](https://github.com/Mystic-Slice/rl-abstention) — [arXiv abs](https://arxiv.org/abs/2601.20126)
- **KARL (arXiv 2604.22779; Gao et al. incl. Maosong Sun; 3 Apr 2026).** Knowledge-Boundary-Aware RL: estimates the model's knowledge boundary online from within-group response statistics and rewards correct answers or guided abstention; two-stage RL avoids the "abstention trap" (over-caution from static rewards). Models, sizes, datasets, metrics not on the abstract page (UNVERIFIED); no code link — [arXiv abs](https://arxiv.org/abs/2604.22779)
- **"Knowing When to Quit: A Principled Framework for Dynamic Abstention in LLM Reasoning" (arXiv 2604.18419; Davidov et al. incl. Rebeschini; ICML 2026, PMLR 306).** Models mid-generation abstention as an explicit action in a KL-regularized RL framework; abstain when the value function falls below the abstention reward; proves this beats natural baselines; domains: math reasoning and toxicity avoidance; mentions selective accuracy; models/sizes not stated on abstract page (UNVERIFIED); no code link — [arXiv abs](https://arxiv.org/abs/2604.18419), [PMLR](https://proceedings.mlr.press/v306/davidov26a.html)
- **RLSR — "Aligning Language Models with Selective Prediction" (arXiv 2607.03528; Luo, Wu, Zhang, Deshwal, Sun; U. Minnesota; 3 Jul 2026; ICML 2026 "Agents in the Wild" workshop).** The one paper found that **optimizes the risk-coverage trade-off directly with RL**: GRPO (std-normalization omitted) where each rollout's reward is **+alpha_i if correct, −alpha_i if wrong**, with alpha_i = H_n − H_{n−r_i} derived from the rollout's verbalized-confidence rank across the pooled batch — a rank-based scheme that provably targets AURC (area under the risk-coverage curve). **No abstain token**: the model emits a `<confidence>` score; abstention happens at inference by thresholding it. Models: **Qwen2.5-7B and Llama-3.1-8B** (both >4B). Training: HotPotQA-Modified, BigMath. Metrics: **AURC, Acc@10/25/50% coverage, ECE, full risk-coverage curves (Figs. 5-6)**. Results: HotPotQA ID AURC 0.44 (RLSR) vs 0.56 (RLVR), 0.51 (RLCR), 0.60 (base); Acc@10 66.0% vs 45.5%/53.5%; BigMath ID AURC 0.24 vs 0.28/0.26/0.41; on MedQA at a 75%-accuracy target, RLSR attains 3.0% coverage at 78.9% accuracy where RLVR never reaches target. Argues calibration ≠ selective prediction (RLCR wins ECE, RLSR wins AURC). Project page: [sun-umn.github.io/RLSR](https://sun-umn.github.io/RLSR); no repo link in fetched content — [arXiv HTML v1](https://arxiv.org/html/2607.03528v1)

**Adjacent reward-design work (calibration rather than abstention)**
- **RLCR — "Beyond Binary Rewards: Training LMs to Reason About Their Uncertainty" (arXiv 2507.16806; Damani et al.; Jul 2025).** GRPO on Qwen2.5-7B; reward = correctness + Brier score (a proper scoring rule) on a verbalized confidence; proves any bounded proper scoring rule yields accurate + calibrated models; in-domain ECE 0.37 → 0.03 (vs RLVR); no abstain action — [arXiv abs](https://arxiv.org/abs/2507.16806)
- **PPO-M / PPO-C — "Taming Overconfidence in LLMs: Reward Calibration in RLHF" (arXiv 2410.09724; Leng, Huang, Zhu, Huang; ICLR 2025).** Finds RLHF induces verbalized overconfidence via the reward model; PPO-M trains the reward model with explicit confidence scores; PPO-C adjusts PPO rewards by the gap to a running reward average; lowers ECE on Llama3-8B and Mistral-7B across six datasets; calibration only, no abstention — [arXiv](https://arxiv.org/pdf/2410.09724), [ICLR poster](https://iclr.cc/virtual/2025/poster/28542)

**Non-RL abstention training (for contrast)**
- **R-Tuning (arXiv 2311.09677; Zhang et al.; NAACL 2024).** Refusal-aware **supervised** instruction tuning: identify questions the pre-trained model gets wrong, append certainty/uncertainty expressions to training targets; refusal transfers as a task-agnostic "meta-skill". SFT, not RL. Code: [github.com/shizhediao/R-Tuning](https://github.com/shizhediao/R-Tuning) — [arXiv abs](https://arxiv.org/abs/2311.09677)

**Classic selective prediction (framing)**
- **SelectiveNet (Geifman & El-Yaniv; ICML 2019).** Deep network with an integrated reject option, trained end-to-end for a target coverage (interior-point method in the loss); evaluated on risk-coverage trade-offs; requires a retrain per target coverage — [PMLR](https://proceedings.mlr.press/v97/geifman19a)
- **Deep Gamblers (Liu et al.; NeurIPS 2019; arXiv 1907.00208).** Converts m-class classification to m+1 classes where the extra class is abstention, with a loss from portfolio theory (doubling rate of gambling); needs almost no architecture change and no per-coverage retraining — [NeurIPS paper](https://papers.NeurIPS.cc/paper_files/paper/2019/file/0c4b1eeb45c90b52bfb9d07943d855ab-Paper.pdf), [ar5iv](https://ar5iv.labs.arxiv.org/html/1907.00208)
- **Risk-coverage metrics for LLMs (eval-only line):** AURC = area under the curve of error rate vs fraction answered, sorted by confidence; E-AURC subtracts an oracle baseline — used in "Entropy Alone is Insufficient for Safe Selective Prediction in LLMs" (arXiv 2603.21172) and others; AURC rewards confidence *ranking*, not calibrated values — [arXiv 2603.21172](https://arxiv.org/pdf/2603.21172), [arXiv 2607.03528](https://arxiv.org/pdf/2607.03528)

### Inferences
- Reward-design convergence: the field has converged on ternary rewards (+1 / r_abs / −penalty) as the canonical RL abstention scheme (RH, TruthRL, Intellectual Humility), which is structurally identical to TrustSQL's RS(c) cases — but no paper found applies this reward *in text-to-SQL* or evaluates with RS(c).
- "Abstention trap" / over-caution is a recognized failure mode (KARL's motivation), suggesting static ternary rewards at high penalty are known to collapse coverage — relevant for any new training recipe.

### Gaps
- TruthRL's backbone model sizes and exact reward values could not be verified from the arXiv abstract page (code repo would settle this).
- KARL's and Knowing-When-to-Quit's model sizes and full metric suites are not on their abstract pages.
- Did not find any paper named "confidence-aware RLHF" verbatim beyond PPO-M/PPO-C; SaySelf/LACIE (other confidence-expression trainers) were not individually verified in this pass.

## Key Question 4 (critical): Has anyone already published RL training + abstention reward + risk-coverage evaluation — especially ≤4B, especially text-to-SQL?

### Takeaway
No single published work found (as of 2026-11-04) combines all three — RL training, an explicit abstention reward, and risk-coverage evaluation — in text-to-SQL at any scale, nor at ≤4B in any domain. Every pairwise combination exists, so the novelty margin is narrow and rests on the triple combination plus the text-to-SQL/RS(c) setting.

### Cited Findings
- **Closest in text-to-SQL — BAR-SQL (Qwen3-1.7B, ≤4B):** GRPO + reward credit for natural-language refusals on unanswerable enterprise queries, but no abstain token, no penalty parameter, **no risk-coverage or RS(c) evaluation**; evaluated by per-category accuracy on its own Ent-SQL-Bench — [arXiv HTML](https://arxiv.org/html/2601.10318)
- **Closest on risk-coverage — RLSR (7B/8B, >4B):** GRPO reward provably targeting AURC + full risk-coverage curves and Acc@coverage, but **no abstention action in training** (inference-time confidence thresholding) and **not text-to-SQL** (QA + math) — [arXiv HTML v1](https://arxiv.org/html/2607.03528v1)
- **Closest at ≤4B with a true abstain action — Reinforced Hesitation (Qwen3-1.7B):** Dr.GRPO + ternary reward + "I don't know" output + Pareto frontiers over the penalty λ, but domain is logic puzzles and it reports error/abstention Pareto plots and conditional accuracy rather than standard risk-coverage curves/AURC — [arXiv HTML v2](https://arxiv.org/html/2511.11500v2)
- **Also ≤4B with abstention reward — Rewarding Intellectual Humility (Granite-3.3-2B, Qwen-3-4B):** RLVR ternary reward with r_abs sweep on multiple-choice MedMCQA/Math; metrics are accuracy and incorrect-rate, no risk-coverage per the abstract — [arXiv abs](https://arxiv.org/abs/2601.20126)
- **Text-to-SQL penalty metric exists but is never RL-trained against:** TrustSQL/EHRSQL-2024 RS(c) is evaluated only with classifiers, thresholds, voting, SFT/self-training — no RL in either paper or in any of the 8 shared-task teams — [TrustSQL HTML](https://arxiv.org/html/2403.15879v6), [EHRSQL overview HTML](https://arxiv.org/html/2405.06673v2)

### Inferences
- The unoccupied cell, per this search: **RL training with an explicit abstention reward, evaluated with risk-coverage curves (or RS(c) swept over c), on a ≤4B model, in text-to-SQL.** A new paper there would be distinguished from BAR-SQL by (i) penalty-calibrated/ternary reward with an explicit abstain output, (ii) selective-prediction evaluation (risk-coverage, AURC, RS(c)), and (iii) public benchmarks (TrustSQL/EHRSQL-2024/Ambrosia+/PRACTIQ) rather than a private enterprise benchmark; distinguished from RLSR by the abstain-as-action training, the ≤4B scale, and the SQL domain; distinguished from Reinforced Hesitation by domain (SQL vs logic puzzles) and by standard risk-coverage reporting.
- Reinforced Hesitation's λ-sweep Pareto frontier is functionally close to a risk-coverage analysis; a reviewer could consider it a near-miss, so any novelty claim should explicitly cite and differentiate it (training-time penalty sweep vs inference-time threshold sweep is a real but subtle distinction).
