# Abstaining SQL Model Passes Feasibility Review

**Verdict: go.** As of 2026-11-04, no published paper combines all three of this project's ingredients — reinforcement-learning training (RL, teaching a model by rewarding good outputs), an explicit abstention reward (paying the model something for saying "I don't know" instead of guessing), and risk–coverage evaluation (a plot of how often the answered queries are wrong against how many queries the model answers) — in text-to-SQL at any model size, nor at 4B parameters or smaller in any domain ([abstention notes, Key Q4](https://arxiv.org/abs/2601.10318)). Every pairwise combination exists, so the novelty margin is narrow and three near-misses must be cited and differentiated: **BAR-SQL** (RL + abstention credit on a 1.7B model, but no penalty parameter and no risk–coverage), **Reinforced Hesitation** (the exact +1/0/−λ reward on a 1.7B model, but on logic puzzles, not SQL), and **RLSR** (RL that directly optimizes the risk–coverage trade-off, but on 7–8B models with no abstain action and no SQL). The budget also clears: the full run matrix is estimated at **$20–36** on verified 2026-11-04 cloud prices, and Modal's verified **$30/month free credit** could cover most of it ([Modal pricing](https://modal.com/pricing)). Five findings change the plan as written in the brief, led by this one: the named primary model **Qwen3.5-2B is a multimodal model with a hybrid attention architecture**, making it the riskiest of the three candidate models for training-tool support, and the brief's statistical centerpiece needs a correction — plain conformal risk control does not actually bound "error among answered queries"; the Learn-then-Test method does.

## The exact combination is unpublished, but three papers crowd it

The RL-for-text-to-SQL field is busy — at least a dozen GRPO-family systems (GRPO = Group Relative Policy Optimization, an RL algorithm that scores a group of sampled answers against each other instead of training a separate judge network) shipped between mid-2025 and 2026 — yet **none of the mainstream systems contains an abstain action**. Arctic-Text2SQL-R1 (7B–32B) rewards 1 for a correct execution result and 0.1 for merely-runnable SQL ([arXiv:2505.20315](https://arxiv.org/abs/2505.20315)); SQL-R1 (3B–14B) uses a composite format/execution/result reward ([arXiv:2504.08600](https://arxiv.org/abs/2504.08600)); Reasoning-SQL (14B) uses partial rewards including an LLM judge ([arXiv:2503.23157](https://arxiv.org/abs/2503.23157)). All three treat every question as answerable, and none reports any selective-prediction metric (selective prediction = letting a model decline some inputs and measuring quality only on what it accepts).

The nearest neighbor in text-to-SQL is **BAR-SQL** (Jan 2026, Li Auto): Qwen3-1.7B trained with GRPO where natural-language refusals on unanswerable enterprise questions earn reward via text similarity to a gold refusal message ([arXiv:2601.10318](https://arxiv.org/html/2601.10318)). It differs from this project on every axis that matters: **no explicit penalty parameter c** (wrong answers simply score zero rather than negative), no abstain token or structured abstain action, **no risk–coverage curves or reliability score**, and evaluation only on its own private enterprise benchmark — no Spider or BIRD numbers at all. The nearest neighbor on the reward itself is **Reinforced Hesitation** (Nov 2025): the literal **+1 correct / 0 abstain / −λ wrong** ternary reward, trained with Dr.GRPO on Qwen3-1.7B — but on Knights-and-Knaves logic puzzles, reporting Pareto frontiers over λ rather than standard risk–coverage curves ([arXiv:2511.11500](https://arxiv.org/html/2511.11500v2)). The nearest neighbor on evaluation is **RLSR** (Jul 2026), whose rank-based reward provably optimizes AURC (area under the risk–coverage curve — one number summarizing the whole answer-vs-error trade-off; lower is better) and which reports full risk–coverage curves — but it trains no abstain action (abstention happens by thresholding a verbalized confidence at inference), uses 7B/8B models, and never touches SQL ([arXiv:2607.03528](https://arxiv.org/html/2607.03528v1)). A fourth near-miss, Rewarding Intellectual Humility (Jan 2026), sweeps the abstain reward on 2B/4B models but only on multiple-choice QA with no risk–coverage reporting ([arXiv:2601.20126](https://arxiv.org/abs/2601.20126)).

Meanwhile, the text-to-SQL reliability literature supplies the metric this project should adopt but has never trained against: TrustSQL's penalty-based Reliability Score **RS(c)** — +1 for a correct answer, 0 for abstaining on an answerable question, −c for any wrong or forbidden answer — is structurally identical to the proposed reward, and neither TrustSQL nor any of the eight EHRSQL-2024 shared-task teams used RL ([arXiv:2403.15879](https://arxiv.org/html/2403.15879v6); [arXiv:2405.06673](https://arxiv.org/html/2405.06673v2)). That convergence is the project's cleanest framing: **train directly against the field's own reliability metric, then report the selective-prediction curves nobody in SQL has published, at a size nobody has tried, with a statistical guarantee on top.** The notes flag honestly that a reviewer could read Reinforced Hesitation's λ-sweep as a near-equivalent analysis, so the write-up must cite it and lean on the three concrete differentiators: domain (SQL with execution-based rewards), standard risk–coverage/RS(c) reporting on public benchmarks, and the conformal-calibration layer none of the near-misses has.

## Synthetic training data with BIRD dev held out survives the license and contamination check

No license blocks the plan. Spider 1.0 and BIRD are **CC BY-SA 4.0** (free to use with attribution; redistributed modified copies of the data must keep the same license), TrustSQL and EHRSQL are **CC BY 4.0** (attribution only), and the Spider 2.0 repo is MIT ([datasets notes](https://bird-bench.github.io/); [yale-lily.github.io/spider](https://yale-lily.github.io/spider); [github.com/glee4810/TrustSQL](https://github.com/glee4810/TrustSQL)). The catch is supervision, not licensing: **only TrustSQL and EHRSQL contain labeled unanswerable questions, and almost none are in training splits** — TrustSQL's ~2,468 unanswerables (about 11.6% of its questions) are test-only, and EHRSQL's unanswerables are 33% of validation/test but absent from training ([arXiv:2403.15879](https://arxiv.org/html/2403.15879v2); [ar5iv 2301.07695](https://ar5iv.labs.arxiv.org/html/2301.07695)). An abstaining model therefore needs synthesized unanswerable training questions regardless of which base dataset is chosen, and the notes found **no prior art on synthesizing unanswerable text-to-SQL questions at scale** — a secondary novelty slot.

Contamination (benchmark questions leaking into a model's pretraining data, which inflates its measured scores) pushes the same direction. No study directly measures Spider or BIRD inside Qwen or Gemma pretraining — that remains UNVERIFIED in both directions — but Spider has been public with its gold SQL since 2018, a GPT-3.5 study found a significant performance drop on an unfamiliar lookalike dataset versus Spider ([arXiv:2402.08100](https://arxiv.org/abs/2402.08100)), and Qwen2.5-Coder's published decontamination list names only code/math benchmarks, not SQL ones ([arXiv:2409.12186](https://arxiv.org/pdf/2409.12186)). The brief's suggested default — **a synthetic generator for training, BIRD dev as the external evaluation** — is the right call, and SynSQL-2.5M provides the proven blueprint: 2.5M samples over 16,583 fully synthetic databases, Apache-2.0, generated entirely with open models via web-table→schema→SQL→back-translated-question steps with execution-based majority voting ([arXiv:2503.02240](https://arxiv.org/html/2503.02240v2)). Injecting unanswerables is then a controlled corruption of that pipeline using TrustSQL's five-type taxonomy (e.g., ask about a column that was deliberately dropped). One caveat from the notes: SynSQL was largely generated *by* Qwen models, so training Qwen3.5 on it adds capability but not knowledge diversity.

The execution checker matters as much as the data. Zhong et al. 2020's **test-suite evaluation** — running predicted and gold SQL against several database instances with different contents so a wrong query can't match the gold result by coincidence — is real, maintained as Spider's official metric, Apache-2.0, and SQLite-based, so it can sit directly inside the reward function ([github.com/taoyds/test-suite-sql-eval](https://github.com/taoyds/test-suite-sql-eval)). BIRD's own harness executes on a single database only. The sharpest trap the notes surfaced is the **empty-result exploit interacting with the abstain reward**: many Spider/BIRD gold queries return empty results (Arctic filtered roughly 1,400 BIRD and 1,700 Spider training examples for exactly this), and a degenerate query that also returns nothing scores as "correct" — earning +1 while honest abstention earns 0, so the RL optimizer would learn to emit junk SQL instead of abstaining on hard questions ([arXiv:2505.20315](https://arxiv.org/html/2505.20315v2)). Filtering gold-empty examples and requiring multi-instance matches must happen before any reward tuning.

## TRL with colocated vLLM wins the stack bake-off; abstain as structured text, not a token

All three candidate models exist, but not as the brief imagined. **Qwen3.5-2B is a multimodal model** (it accepts images and video) with layers alternating Gated DeltaNet and attention — a hybrid architecture that needed vLLM nightly at release and that **Unsloth's embedded vLLM cannot serve** (`fast_inference=False` required, forfeiting Unsloth's main speed advantage) ([Qwen/Qwen3.5-2B card](https://huggingface.co/Qwen/Qwen3.5-2B); [Unsloth RL guide](https://unsloth.ai/docs/basics/reinforcement-learning-rl-guide)). Its card also warns the 2B size is "more prone to thinking loops." **"Gemma 4 E2B" is really 5.1B total parameters in memory** (2.3B active per token), so its training footprint is that of a 5B model ([google/gemma-4-E2B-it card](https://huggingface.co/google/gemma-4-E2B-it)). SmolLM3-3B is the boring, best-supported fallback ([HuggingFaceTB/SmolLM3-3B card](https://huggingface.co/HuggingFaceTB/SmolLM3-3B)). Upstream vLLM supports Qwen3.5 in-tree by v0.19.0, including a LoRA fix ([vLLM v0.19.0 notes](https://github.com/vllm-project/vllm/releases/tag/v0.19.0)), so the recommendation is **TRL's GRPOTrainer (v1.17.x) with vLLM colocate mode** — vLLM shares the single training GPU, which is the documented default — with LoRA (low-rank adapters: training a small add-on instead of all the weights) via `peft_config`, and reward functions that are arbitrary, even async, Python, so executing SQL inside the reward is first-class ([TRL GRPOTrainer docs](https://huggingface.co/docs/trl/main/en/grpo_trainer)). The `verifiers` library adds multi-turn machinery this single-turn project doesn't need and churned heavily through 2026; Unsloth stays as the fallback if the control model needs its VRAM efficiency.

The abstain mechanism should be **structured output** — a JSON object like `{"sql": ..., "abstain": bool}` or a reserved tag parsed by the reward function — **not a new vocabulary token**. Every RLVR-era abstention paper the notes found uses emitted text; the added-token approach comes from the continued-pretraining literature and would force the embedding and output layers into training (a large VRAM hit at Qwen3.5's 150K–262K-token vocabularies), collide with TRL's fused output-layer scoring path, which raises an error on exactly that configuration, and complicate adapter syncing into vLLM ([TRL releases](https://github.com/huggingface/trl/releases); [arXiv 2412.06676](https://arxiv.org/abs/2412.06676)). Loss settings converge across sources on: `loss_type="dr_grpo"` with `scale_rewards=False` (Dr. GRPO — a GRPO variant that removes two normalizations shown to bias response length), KL coefficient β=0 (which also skips loading the reference model, saving memory), group size 8, learning rate ~1e-6, clip 0.2, and a completion cap near 1024–2048 tokens with truncated completions masked, since the 2B model's thinking-loop proneness argues for a hard cap ([arXiv:2503.20783](https://arxiv.org/html/2503.20783v2); [TRL docs](https://huggingface.co/docs/trl/main/en/grpo_trainer)). The known failure mode to watch is **abstention collapse**: a fixed abstain reward can tip the model into refusing everything at high penalty c (the "abstention trap" that motivated KARL's dynamic rewards), which is precisely why the run matrix sweeps c and why training curves must log abstention rate per step ([alphaXiv 2607.10738](https://www.alphaxiv.org/abs/2607.10738); [arXiv 2604.22779](https://arxiv.org/abs/2604.22779)).

## The budget clears with room to spare, pending one measured number

At prices verified on 2026-11-04, a RunPod A100 80GB costs **$1.79/hr** on Secure Cloud ($1.19 Community), a community RTX 4090 is **$0.34/hr**, and Modal's A100 runs about **$2.50/hr with $30/month of free Starter credit** ([RunPod pricing](https://www.runpod.io/pricing); [Modal pricing](https://modal.com/pricing)). The cost model is steps × prompts per step × group size × tokens per completion ÷ end-to-end throughput × hourly price. The honest gap: **no published end-to-end GRPO throughput benchmark exists for a ~2B model with LoRA and vLLM on a single GPU** — the central planning number of 800–2,000 output tokens/sec (an estimate triangulated from Unsloth's ~4,000 tokens/sec pure-generation figure for a 3B model, Mini-R1's 45–60 s/step on 4×H100, and a community 7B SQL run) is the single most uncertain input, which is why a **20-step smoke test (under $0.60)** gates every full run ([Mini-R1 blog](https://huggingface.co/blog/open-r1/mini-r1-contdown-game); [Unsloth GRPO docs](https://unsloth.ai/docs/basics/reasoning-grpo)). At the central estimate, a 300-step run costs about **$2.45**, and the full matrix — one accuracy-only baseline, three penalty values × two seeds, one optional control-model run, 8 runs total — lands at **$20–36 including overhead**, with the pessimistic case still inside $30–50 and two large safety valves: Modal's free credit (~12 A100-hours/month) and the $0.34/hr 4090 if the 2B model fits in 24GB, which Unsloth's VRAM guidance strongly suggests. Comparable precedent says the budget is sane: TinyZero reproduced R1-style RL on a 3B model for a claimed under-$30 ([TinyZero README](https://github.com/Jiayi-Pan/TinyZero)).

## The guarantee needs Learn-then-Test, and the risk–coverage evaluation is where the paper lives

The brief's calibration step contains a subtle statistical trap the notes resolved cleanly. Conformal risk control (CRC — a recipe that picks one confidence cutoff on held-out data so a chosen error target provably holds) bounds the **expected joint rate of "answered AND wrong"** — an unconditional quantity — and its guarantee holds on average over re-draws of the calibration set ([arXiv:2208.02814](https://arxiv.org/abs/2208.02814)). But the promise users will read into "error ≤ α on the queries it answers" is **selective risk: a conditional error rate, a ratio of two quantities — and plain CRC does not bound ratios**. The right tool is **Learn-then-Test (LTT)** — a framework that treats each candidate cutoff as a statistical hypothesis test ("is the true error above α?") and keeps only cutoffs where that hypothesis is rejected, yielding a guarantee that holds with probability ≥ 1−δ over the calibration draw ([arXiv:2110.01052](https://arxiv.org/abs/2110.01052)). Concretely: walk a grid of cutoffs from most to least conservative, run an exact binomial test on the answered calibration points at each, and stop at the first failure. Simple threshold-matching on a calibration split, by contrast, gives no finite-sample guarantee at all — the test error lands above target roughly half the time at the boundary ([arXiv:1705.08500](https://arxiv.org/abs/1705.08500)). The confidence signal to calibrate should sit *on top of* the RL policy, because the learned abstain decision is binary and cannot be thresholded: sequence log-probability (the model's own probability for the full query — cheap and, per published SQL-specific evidence, stronger than asking the model to self-assess) is the primary signal, with k-sample execution agreement as the stronger, k-times-costlier alternative ([arXiv:2411.16742](https://arxiv.org/abs/2411.16742)). The guarantee's one assumption — new queries must look statistically like the calibration data — is also its best experiment: **calibrate on one schema family, test on another, and measure how far realized error overshoots α.** No published calibration-transfer study exists for text-to-SQL, and the best proxy (fine-tuned verifiers dropping from ~0.78 to ~0.66 AUROC on unseen schemas) predicts visible breakage worth reporting ([arXiv:2607.06799](https://arxiv.org/abs/2607.06799)).

Evaluation then assembles the standard kit, none of it LLM-judged: execution accuracy via multi-instance test suites, coverage, selective risk, AURC, TrustSQL's RS(c) at c ∈ {0, 10, N}, tokens per query, and local GGUF latency; baselines are the base model prompted to abstain, self-consistency thresholding, accuracy-only GRPO, and 1–2 frontier APIs prompted to abstain — with the striking published anchor that **frontier models abstain less than 1% of the time while erring over 10%** when prompted zero-shot ([arXiv:2511.11500](https://arxiv.org/html/2511.11500v2)). Statistics follow the NeurIPS-2021 rliable playbook: at least 2 seeds, bootstrap confidence intervals (re-sampling the results many times to see how much each number wobbles) over both test items and seeds, interquartile means, and — because conformal guarantees are averages over calibration draws — re-drawing the calibration/test split many times to show the distribution of realized error around α ([arXiv:2108.13264](https://arxiv.org/abs/2108.13264)). Positioning writes itself from the BI-copilot survey: Snowflake, Databricks, ThoughtSpot, and Hex all manage wrongness through **human curation before the question and human inspection after the answer** — semantic layers, verified-query libraries, show-the-SQL — and none publishes an abstention rate, a refusal threshold, or any calibrated runtime confidence (Snowflake's `confidence` API field merely reports whether a pre-verified query was reused) ([Cortex Analyst REST API docs](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-analyst/rest-api); [Talk to Genie docs](https://docs.databricks.com/aws/genie/talk-to-genie)). An open benchmark plus a small reference model with measured, guaranteed operating points fills the unoccupied middle: calibrated behavior at answer time.

## Conclusion

The project survives its own kill-switch question, but the novelty now lives in the *combination and the rigor*, not in any single ingredient — which changes how the work should be framed and sequenced. Train against the field's existing reliability metric (RS(c)) rather than inventing one; cite BAR-SQL, Reinforced Hesitation, and RLSR in the first paragraph of any write-up and differentiate on domain, explicit abstain action, public benchmarks, and the guarantee layer; and treat the Learn-then-Test selective-risk certificate plus the schema-shift stress test as the headline contributions, since both are unoccupied even outside SQL at this scale. The two decisions that most de-risk the four weeks are made cheap by the findings: a sub-$1 smoke test converts the only unmeasured cost input into a measured one before any budget commitment, and SmolLM3-3B stands by as a drop-in if Qwen3.5-2B's hybrid multimodal architecture fights the tooling. The deepest design insight from the notes is the interaction between reward hacking and abstention: an exploit that merely inflated accuracy numbers in prior work (empty-result matching) actively *punishes honesty* once abstention earns 0, so data filtering and multi-instance execution checks are not evaluation hygiene here — they are what makes the reward mean what it says.
